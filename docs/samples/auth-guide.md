# 인증 서비스 확인 가이드

> 가상 실습 자료입니다. 아래 내용은 실제 운영 지시가 아닙니다.

| 항목 | 값 |
| --- | --- |
| 문서 ID | `auth-guide` |
| 서비스 ID | `auth-service` |
| 담당팀 | 플랫폼팀 (`platform-team`) |
| 이 서비스에 직접 의존하는 서비스 | 주문 서비스, 결제 서비스, 알림 서비스 |

인증 서비스는 가상 사용자의 인증 상태를 확인합니다. 이 예제에서는 주문·결제·알림 서비스가 모두 인증 서비스를 사용한다고 가정합니다.

## 실습 시나리오

“인증 서비스에 문제가 생기면 어디를 확인해야 하는가?”라는 질문에 답하기 위해 다음 정보를 모읍니다.

1. `auth-service`의 `OWNED_BY` 관계를 조회해 담당팀이 플랫폼팀인지 확인합니다.
2. 인증 서비스로 **들어오는** `DEPENDS_ON` 관계를 조회합니다. 관계의 시작점인 서비스가 인증 서비스를 사용합니다.
3. 직접 의존하는 주문·결제·알림 서비스를 영향 후보로 기록합니다.
4. 주문 서비스 → 결제 서비스 → 인증 서비스라는 2홉 경로도 찾아봅니다.
5. 같은 서비스가 여러 경로에서 발견될 때 한 번만 표시하고, 최소 홉 수를 확인합니다.

주문 서비스는 인증 서비스에 직접 의존하므로 최소 홉 수는 1입니다. 2홉 경로가 있다고 해서 결과에 주문 서비스가 두 번 나올 필요는 없습니다. `queries/04_impact.cypher`에서 이를 실습할 수 있습니다.

## 결과 해석

관계는 잠재적인 영향 경로를 뜻합니다. 실제 장애 여부나 장애의 크기는 표현하지 않습니다. 실습 조회는 최대 5홉까지만 탐색하며, 결과에 없다는 이유로 5홉 밖의 영향이나 데이터에 기록되지 않은 의존성이 없다고 결론 내리면 안 됩니다.

`auth-guide` 노드는 `DESCRIBES` 관계로 인증 서비스에 연결됩니다. `source`는 `docs/samples/auth-guide.md`이며, 이 경로를 통해 답변의 근거가 된 원문을 찾을 수 있습니다.
