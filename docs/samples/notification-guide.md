# 알림 서비스 확인 가이드

> 가상 실습 자료입니다. 아래 내용은 실제 운영 지시가 아닙니다.

| 항목 | 값 |
| --- | --- |
| 문서 ID | `notification-guide` |
| 서비스 ID | `notification-service` |
| 담당팀 | 플랫폼팀 (`platform-team`) |
| 직접 의존하는 서비스 | 인증 서비스 |

알림 서비스는 가상의 알림 발송 요청을 처리하며, 요청자의 인증 상태를 확인하기 위해 인증 서비스를 사용한다고 가정합니다. 실제 이메일·문자·메신저 발송 기능은 구현하지 않습니다.

## 실습 시나리오

“플랫폼팀이 담당하는 서비스와 관련 문서를 모아 보고 싶다”는 질문에 답하기 위해 다음 정보를 모읍니다.

1. `platform-team` 노드를 찾습니다.
2. 이 팀으로 들어오는 `OWNED_BY` 관계를 따라 인증 서비스와 알림 서비스를 찾습니다.
3. 각 서비스로 들어오는 `DESCRIBES` 관계를 따라 관련 문서를 찾습니다.
4. 인증 서비스의 영향 후보를 조회하면 알림 서비스도 포함되는지 확인합니다.

이 예제에는 주문 서비스와 알림 서비스 사이의 직접 의존 관계가 없습니다. 따라서 주문 서비스와 그 직접 의존 서비스만 조회할 때 알림 서비스는 포함되지 않습니다. 같은 인증 서비스를 사용한다는 사실만으로 주문 서비스가 알림 서비스에 의존한다고 추론하지 않습니다.

`notification-guide` 노드는 `DESCRIBES` 관계로 알림 서비스에 연결됩니다. `source`는 `docs/samples/notification-guide.md`입니다.
