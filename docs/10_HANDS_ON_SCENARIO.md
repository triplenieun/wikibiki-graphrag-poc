# 문서 두 개로 따라 하는 GraphRAG 실습

문서를 등록하고 LLM이 제안한 관계를 직접 확인한 뒤, 검색 근거와 답변에 반영되는 과정을 확인합니다.
두 문서는 가상 사례입니다. `seed_graph`는 이 문서들을 자동 적재하지 않습니다. 직접 등록하는 실습용입니다.

## 1. 준비와 실행 순서

이미 실행 중인 앱의 **문서 등록**(`/documents/`), **GraphRAG**(`/graphrag/`), **문서 관리**(`/documents/manage/`) 메뉴를 사용합니다.
외부 미리보기에서는 안내받은 HTTPS 주소에서 같은 메뉴로 이동합니다. 임시 주소 자체는 저장소에 고정하지 않습니다.

1. 문서 A 입력 → 관계 추출 → 검토 → 저장.
2. 재고 서비스로 검색하여 A의 내용이 반영됐는지 확인.
3. 문서 B 입력 → 관계 추출 → 기존 재고 서비스 연결 확인 → 저장.
4. 출고 서비스 검색과 인증 서비스의 영향 후보 검색.
5. 선택 실습: 문서 A의 숫자를 수정하고 다시 검색.

**문서 A를 저장한 다음 B를 추출하세요.** 추출만 한 A는 아직 DB에 없으므로 B가 기존 노드로 찾을 수 없습니다.
같은 문서를 새 등록 화면에서 여러 번 추출·저장하면 별도 문서가 생깁니다. 내용을 고칠 때는 기존 문서를 수정합니다.

## 2. 문서 A: 재고 서비스

- 제목: `실습 재고 서비스 운영 안내`
- 출처: `practice/demo-inventory-guide`
- 본문: [demo-inventory-guide.md](samples/demo-inventory-guide.md)의 내용을 붙여 넣거나 해당 파일을 선택합니다.

파일 선택은 본문을 채우는 기능입니다. 제목·출처도 위 값으로 입력하세요. 출처를 적는 것만으로 서버가 파일을 읽지는 않습니다.
모바일에서는 문서의 텍스트를 복사해 본문에 붙여 넣으면 됩니다.

**관계 추출하기**를 누릅니다. 현재 앱의 설정에 따라 사내 LiteLLM 또는 로컬 Ollama가 후보를 제안합니다.
추출만으로 Neo4j는 변경되지 않습니다.

### 노드 확인

| 이름 | 종류 | ID 예시 | 처리 |
|---|---|---|---|
| 실습 재고 서비스 | Service | `demo-inventory-service` | 처음에는 새 노드 |
| 실습 재고팀 | Team | `demo-inventory-team` | 처음에는 새 노드 |
| 인증 서비스 | Service | `auth-service` | 기존 노드 재사용 |

새 노드 ID는 LLM 결과가 다를 수 있습니다. 이 가이드와 맞추려면 미리보기에서 위 ID로 수정하세요.
기존 노드가 이미 있으면 화면의 기존 노드 연결로 선택합니다. 문서 ID는 자동 생성되므로 직접 정하지 않습니다.

### 반드시 확인할 관계

| 시작 | 관계 | 도착 | 본문에서 복사할 근거 문장 |
|---|---|---|---|
| 현재 문서 A | 설명 / `DESCRIBES` | 실습 재고 서비스 | 실습 재고 서비스는 실습 재고팀이 담당합니다. |
| 실습 재고 서비스 | 담당팀 / `OWNED_BY` | 실습 재고팀 | 실습 재고 서비스는 실습 재고팀이 담당합니다. |
| 실습 재고 서비스 | 의존 / `DEPENDS_ON` | 인증 서비스 | 실습 재고 서비스는 사용자 인증을 위해 인증 서비스를 호출하며, 인증 서비스에 의존합니다. |

모델이 A에서 인증 서비스로 향하는 `DESCRIBES`도 제안할 수 있습니다. 본문이 뒷받침하면 유지할 수 있습니다.
추출 개수를 맞추는 것보다 **연결 대상·방향·근거**가 올바른지 확인하세요.

`재고 → 인증`은 재고가 인증을 호출한다는 뜻입니다. 반대 방향으로 나오면 수정합니다.
없는 관계는 **관계 추가**로 보완하고, 근거 문장은 위 문장처럼 **본문의 연속된 문장을 그대로** 넣습니다.
제목·출처·새로 쓴 요약은 관계 근거로 사용하지 않습니다.

`3초`와 확인 순서는 문서 본문에 남는 정보입니다. 숫자나 모든 문장을 노드·관계로 만들 필요는 없습니다.
관계는 검색할 문서를 찾는 데 쓰이고, 문서의 세부 내용은 LLM 답변의 근거로 쓰입니다.

**서비스·팀의 연결, 관계의 방향, 근거 문장을 확인했습니다.**를 체크한 뒤 **검토한 내용 저장하기**를 누릅니다.

## 3. 문서 A 검색하기

저장 후 **GraphRAG에서 질문하기**로 이동합니다. **대상 서비스를 직접 `실습 재고 서비스`로 확인**하세요.
문서가 여러 서비스를 설명하면 이동 링크가 다른 서비스를 먼저 선택할 수 있습니다.

- 탐색 방식: **담당팀 · 운영 문서**
- 질문: `실습 재고 서비스의 담당팀과 직접 의존하는 서비스를 알려줘.`
- 먼저 **근거만 조회** → 그래프·근거 문서 확인 → **답변 생성**.

다음을 확인합니다.

1. 관계 그래프에 `실습 재고 → 실습 재고팀`, `실습 재고 → 인증`이 나타납니다.
2. 근거 문서에 **실습 재고 서비스 운영 안내**의 제목과 본문이 있습니다.
3. **Cypher 기록**에서 대상 서비스 확인, 의존 방향 1홉 탐색, 담당팀, 근거 문서 조회를 볼 수 있습니다.
4. 답변에 실습 재고팀과 인증 서비스가 포함되고 검색된 근거를 인용합니다.

이어 `실습 재고 서비스의 재고 조회 요청 타임아웃은 몇 초인가요?`라고 질문합니다.
문서 A의 **3초**가 답변 근거입니다. `[G]`는 그래프 사실이고 `[D숫자]`는 해당 조회의 문서 근거입니다.
문서 번호는 조회마다 달라질 수 있으므로 `[D1]`로 고정해서 판단하지 말고 제목과 원문으로 대조하세요.

## 4. 문서 B: 출고 서비스

A의 저장·검색 확인을 마친 뒤 새 문서를 등록합니다.

- 제목: `실습 출고 서비스 운영 안내`
- 출처: `practice/demo-fulfillment-guide`
- 본문: [demo-fulfillment-guide.md](samples/demo-fulfillment-guide.md)의 내용을 붙여 넣거나 파일을 선택합니다.

노드는 다음과 같이 확인합니다.

| 이름 | 종류 | ID 예시 | 처리 |
|---|---|---|---|
| 실습 출고 서비스 | Service | `demo-fulfillment-service` | 새 노드 |
| 실습 출고팀 | Team | `demo-fulfillment-team` | 새 노드 |
| 실습 재고 서비스 | Service | A에서 저장한 ID | 기존 노드 재사용 |

필수 관계는 다음 세 가지입니다. 누락·방향 오류가 있으면 미리보기에서 수정합니다.

| 시작 | 관계 | 도착 | 본문 근거 |
|---|---|---|---|
| 현재 문서 B | `DESCRIBES` | 실습 출고 서비스 | 실습 출고 서비스는 실습 출고팀이 담당합니다. |
| 실습 출고 서비스 | `OWNED_BY` | 실습 출고팀 | 실습 출고 서비스는 실습 출고팀이 담당합니다. |
| 실습 출고 서비스 | `DEPENDS_ON` | 실습 재고 서비스 | 실습 출고 서비스는 출고 가능한 수량을 확인하기 위해 실습 재고 서비스를 호출하며, 실습 재고 서비스에 의존합니다. |

B에서 재고 서비스로 향하는 설명 관계가 추가되어도 본문이 뒷받침하면 사용할 수 있습니다.
확인 체크박스를 선택하고 저장합니다. 저장 후 GraphRAG에서 **실습 출고 서비스**를 직접 선택합니다.

## 5. 복사해서 사용할 질문

각 질문에서 **근거만 조회**로 원문을 먼저 확인한 뒤 **답변 생성**을 사용합니다.
답변 문구는 모델에 따라 달라집니다. 아래 사실과 근거가 맞는지 확인하는 실습입니다.

| 대상 서비스 | 탐색 방식 | 질문 | 확인할 결과 |
|---|---|---|---|
| 실습 재고 서비스 | 담당팀 · 운영 문서 | 실습 재고 서비스의 담당팀과 직접 의존하는 서비스를 알려줘. | 실습 재고팀, 인증 서비스 |
| 실습 재고 서비스 | 담당팀 · 운영 문서 | 실습 재고 서비스의 재고 조회 요청 타임아웃은 몇 초인가요? | 문서 A의 3초 |
| 실습 출고 서비스 | 담당팀 · 운영 문서 | 실습 출고 서비스는 어떤 서비스에 직접 의존하고 어느 팀이 담당하나요? | 실습 재고 서비스, 실습 출고팀 |
| 실습 출고 서비스 | 담당팀 · 운영 문서 | 실습 출고 서비스의 처리 제한시간과 실습 재고 서비스의 조회 타임아웃을 각각 알려줘. | 문서 B의 8초와 문서 A의 3초 |
| 실습 출고 서비스 | 담당팀 · 운영 문서 | 출고 요청이 실패하면 무엇을 먼저 확인하고 어느 팀에 문의해야 하나요? | 재고 상태 → 출고 처리 로그 확인, 실습 출고팀 문의 |
| 인증 서비스 | 장애 영향 후보 | 인증 서비스에 장애가 나면 실습 재고 서비스와 실습 출고 서비스에 어떤 잠재 영향이 있나요? | 실습 재고 → 인증, 실습 출고 → 실습 재고 → 인증의 의존 경로 |
| 실습 재고 서비스 | 담당팀 · 운영 문서 | 실습 재고 서비스를 재시작하는 정확한 명령어를 알려줘. | 문서에 명령어가 없으므로 현재 근거로 확인할 수 없다고 답해야 함 |

기본 탐색은 **선택 서비스와 직접 의존하는 서비스 1홉**, 영향 후보 탐색은 **대상에 의존하는 역방향 최대 5홉**입니다.
재고 서비스의 기본 검색 그래프에 출고 서비스가 나오지 않아도 정상입니다. 반대로 출고의 기본 검색은 재고를 포함합니다.
다만 B가 재고를 설명하도록 연결됐다면, 재고 검색의 근거 문서에는 B도 나올 수 있습니다.

인증 서비스의 영향 후보에는 기존 주문·결제·알림 등도 함께 나올 수 있습니다. 실습 서비스 두 개만 나와야 하는 것은 아닙니다.
의존 관계는 **잠재 영향**의 근거이며 실제 장애가 발생했음을 증명하지 않습니다.

### 관계 추출에서 오류가 나면

LLM은 같은 문서에서도 잘못된 JSON이나 노드 ID를 반환할 수 있습니다. 특히 작은 로컬 모델에서는 첫 시도에 형식 검증 오류가 날 수 있습니다.
오류가 표시된 경우 본문을 유지하고 **관계 추출하기**를 다시 눌러 보세요. 추출 단계이므로 재시도해도 문서가 중복 저장되지 않습니다.
반복되면 문서를 더 짧게 나누거나 LLM 연결·모델 설정을 확인합니다. 미리보기가 표시되었다면 위 표와 비교해 누락·방향·근거 문장을 수정합니다.
추출 성공이나 저장 성공만으로 내용까지 정확하다고 판단하지 말고, 관계와 검색 근거를 직접 확인하세요.

## 6. 선택 실습: 수정·삭제 반영 확인

### 숫자 수정

1. 문서 관리에서 **실습 재고 서비스 운영 안내**를 찾아 수정합니다.
2. 본문의 `타임아웃은 3초입니다.`를 `타임아웃은 7초입니다.`로 변경합니다.
3. **관계 다시 추출하기** → 기존 노드·관계 검토 → 확인 체크 → **수정한 내용 저장하기**.
4. 재고 서비스의 같은 질문을 다시 조회하고 답변을 생성합니다.
5. 근거 문서에 **7초**가 표시되고 새 답변에도 7초가 반영되는지 확인합니다.

새 문서 등록으로 7초짜리 문서를 추가하면 3초와 7초 두 문서가 함께 남을 수 있습니다. 이 실습에서는 반드시 기존 문서를 수정하세요.

### 삭제

문서 관리에서 **실습 출고 서비스 운영 안내**를 삭제하고 다시 검색하면 B가 근거 문서에서 빠집니다.
B만 뒷받침하던 앱 생성 관계는 제거되지만 서비스·팀 노드는 남습니다.
다른 문서가 같은 관계를 뒷받침하면 그 관계는 유지되므로, 삭제 후 서비스 자체가 없어져야 한다고 판단하지 않습니다.

문서가 여러 서비스의 사실을 모으는 방식은 [GraphRAG 가이드](07_GRAPHRAG_GUIDE.md),
추출·검토 규칙은 [등록 가이드](08_DOCUMENT_INGESTION.md), 공유 관계의 유지 기준은 [관리 가이드](09_DOCUMENT_MANAGEMENT.md)를 참고하세요.
